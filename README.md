# 巨大デジタル金魚すくい

> スマホをポイにして、みんなで壁一面の金魚をすくう。

壁一面の巨大スクリーンに映る夏祭りの水槽を、最大4人が **自分のスマートフォンそのものをポイとして**
動かして金魚をすくうデジタル金魚すくいです。アプリのインストールは不要。QRコードを読んで
Webページを開くだけで参加できます。

画面上のボタン・スワイプ・ジョイスティックは **一切ありません**。スマートフォンを傾け、前に倒し、
水に入れるように下げ、金魚をすくうように持ち上げる — その身体動作だけでポイを操作します。
捕まえた金魚は、自分のスマートフォンの中の金魚ボウルで泳ぎ続けます。

## 1. 動かす

```bash
npm install
npm run build
npm run start:https
```

起動するとターミナルに3つのURLが出ます。

| 用途 | URL |
|---|---|
| 巨大スクリーン | `https://<LAN IP>:3000/screen/FESTIVAL01` |
| 参加（スマホ） | `https://<LAN IP>:3000/join/FESTIVAL01` |
| 運営コンソール | `https://<LAN IP>:3000/admin?room=FESTIVAL01` |

開発中は `npm run dev`（ホットリロード）または `npm run dev:https` を使ってください。

### なぜ HTTPS が必要か

iOS Safari と Chrome は **セキュアコンテキストでしか DeviceMotion / DeviceOrientation を
公開しません**。会場のLANには公開DNSも証明書もないため、`start:https` は
`certs/` に自己署名証明書を自動生成します（このPCのLAN IPすべてを SAN に含めます）。
スマートフォン側では初回に一度だけ証明書の警告を承認してください。

`localhost` で開く場合はHTTPでもセンサーが使えます（PCでのデバッグ用）。

### トンネルで一時公開する（証明書警告なし）

正規のHTTPS証明書付きの公開URLが手に入り、
**スマホ側の証明書警告が一切不要**になります。

```bash
brew install cloudflared   # 初回のみ。アカウント不要
npm run build
npm run tunnel
```

既定は **Cloudflare Quick Tunnel** です。`TUNNEL=ngrok npm run tunnel` で ngrok も
使えますが、**ngrok無料プランはスマホでは非推奨**：ブラウザ確認ページの cookie を
持たない端末（アプリ内ブラウザ等）では JS/CSS のリクエストにまで HTML が返り、
「SyntaxError: Unexpected token '<'」でアプリが起動できません（実機で確認済み）。

起動すると2通りのURLが表示されます。

| 構成 | 使いどころ |
|---|---|
| **すべて公開URL経由** | リモートデモ・一番かんたん。スクリーンもスマホも同じngrok URLを開くだけ |
| **ハイブリッド（推奨）** | スクリーンは `localhost`（表示遅延ゼロ）、QRだけ公開URLを指す。スクリーンURLに付く `?join=…` がQRの向き先を差し替えます |

```bash
ROOM_ID=MATSURI npm run tunnel                     # 部屋IDを変える
TUNNEL=ngrok npm run tunnel                        # ngrokを強制（非推奨・上記参照）
NGROK_DOMAIN=my-name.ngrok-free.app npm run tunnel # ngrok予約ドメイン
```

注意:
- インターネット往復のぶん操作遅延が **+30〜150ms** 増えます。低遅延が欲しい本番は
  同一LAN + `npm run start:https`（自己署名証明書）を推奨

## 2. 会場の設営

必要なもの:

- 巨大スクリーン or プロジェクター（16:9 / 1920×1080以上、4Kが理想）
- ゲーム実行PC（GPU付き推奨）
- Wi-Fi（PCと参加者のスマホが同じLANにいるのが理想）
- 参加者のスマートフォン

手順:

1. PCで `npm run start:https` を実行。
2. ブラウザで `/screen/FESTIVAL01` を開き、**全画面（F11 / ⌃⌘F）** にする。
3. 待機画面にQRコードが出ます。参加者はそれを読むだけ。
4. 参加者が「参加する」をタップ → センサー許可 → 数秒でゲームが自動的に始まります。

ROOM ID はURLに含まれます。参加者にコードを入力させる必要はありません。
複数の水槽を同時に動かす場合は `/screen/<別のID>` を開くだけで新しい部屋ができます。

## 3. 遊びかた（参加者向けの説明は不要ですが、念のため）

```
QRを読む → 参加する → センサー許可 → スマホを自然に構える（自動キャリブレーション）
  ↓
移動: 画面の右側を押すと右へ、左側を押すと左へ（上のほうで奥へ、下のほうで手前へ）
スマホを下にかたむける → ポイが水の中へ（深くかたむけるほど深く）
金魚をポイの上に入れる
スマホを上にかたむける → すくい上げ → 捕獲成功
  ↓
自分のスマホのボウルに、いま捕まえた金魚が入って泳ぎ始める
```

**かたむける速さがすべて**です。ゆっくり上げれば紙は破れません。
勢いよく返すと、本物と同じように濡れた紙が破れます。
左右のかたむきは入水・すくいに影響しません。

> 補足: タッチでの移動は元仕様書§23の「タッチ操作禁止」を実地テストに基づく
> オーナー判断で改訂したものです（2026-08-26）。入水・すくいは引き続き
> モーションセンサーのみで行います。

**勢いよく振り上げるとポイが破れます。** 濡れているほど、重い金魚を乗せているほど破れやすい。
破れても3秒で新しいポイが配られます。脱落はありません。

| 金魚 | 得点 | レア度 |
|---|---|---|
| 赤金魚 | 100pt | Common |
| 赤白金魚 | 200pt | Common |
| 黒金魚 | 300pt | Rare |
| 出目金 | 500pt | SuperRare |
| 金色金魚 | 1000pt | Legendary |

レア金魚ほど臆病で、ポイから早く逃げます。

## 4. 運営操作

### スクリーン上のSTARTボタン

待機画面に **START** と **全員退出** が出ます（プロジェクターPCのマウス／キーボード用）。

- **START** … 手動でラウンド開始。**スペースキー / Enter** でも開始できます
- **全員退出** … 見つからないタブが席を占有しているときの掃除用

通常はスマホが1台つながって数秒で自動開始しますが、
**実際に入力を送っている端末がいる場合だけ**自動開始します。
タブを開いたまま放置された「幽霊席」が延々とラウンドを始めてしまうことはありません。
45秒間まったく入力が来ない席は自動で退出扱いになります（再参加はタップ1回）。

## 4b. 運営コンソール

`/admin?room=FESTIVAL01`

- ゲーム開始 / リセット / 強制終了
- ゲーム時間（60〜90秒）、金魚の数（10〜200匹）、最大人数
- ポイ破損時のペナルティ、音声、高品質描画の切り替え
- 接続中のプレイヤー、センサー状態、ポイ耐久の確認
- **BOTの追加**: スマホが1台しかないときに複数人プレイを予行演習するための機能

通常運転では、プレイヤーが揃うと自動的にゲームが始まり、終了後は自動的に待機画面へ戻ります。
運営が何も操作しなくても一日中回り続けます。

## 5. 構成

```
Smartphone (sensors 60Hz, binary)  ──┐
                                     ├── Socket.IO ── Node.js Game Server (60Hz, authoritative)
Admin browser ───────────────────────┤                  ├ PoiSimulation
                                     │                  ├ FishSimulation (Boids, 200匹)
                                     ▼                  ├ CaptureSystem (所有権の裁定)
                          Big Screen Browser            └ Scoring / Lifecycle
                          Three.js + R3F
```

- 金魚・ポイ・スコア・捕獲判定はすべて **サーバー権威**。クライアント単独の捕獲判定はしません。
- 魚は30Hz、ポイは60Hzで別々に配信。ポイだけを高頻度・低遅延で送ることで、
  「スマホを動かしてから画面のポイが動くまで」を体感50〜70msに抑えています。
- 詳細は [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md)、
  モジュールAPIは [docs/MODULE_CONTRACTS.md](./docs/MODULE_CONTRACTS.md) を参照。

## 6. 開発

```bash
npm run dev          # http://localhost:3000
npm run dev:https    # 実機のセンサーを使うときはこちら
npm run typecheck
npm run test         # 133 tests（センサー・物理・捕獲判定・通信・スコア）
npm run smoke        # 起動中のサーバーに対する通し確認
```

### 会場での通し確認

`npm run smoke` は、実際のSocket.IO経由でスクリプト化されたプレイヤーを参加させ、
自動開始 → キャリブレーション → カウントダウン → 金魚を追いかけてすくう →
わざと乱暴に振ってポイを消耗させる → TIME UP → 結果、までを一通り実行します。
WebGL以外のすべての層（サーバー権威のシミュレーション、バイナリ通信、捕獲判定、
耐久モデル、スコア、特別賞）を通しで確認できるので、**開場前に一度流してください**。

```bash
URL=https://192.168.3.6:3000 ROOM=FESTIVAL01 npm run smoke
```

### PCだけでデバッグする

`/join/FESTIVAL01?debug=1` を開くと、センサーの代わりにキーボードでポイを操作できます
（矢印キー/WASDで移動、Spaceを押している間は水中、離すとすくい上げ）。
`/screen/FESTIVAL01?debug=1` はFPSと通信状態のオーバーレイを表示します。

**デバッグ入力は開発用です。** 完成形の操作方式はモーションセンサーのみです。

### 3Dアセットの差し替え

金魚もポイも環境もすべて手続き生成なので、外部アセットは不要です。
より作り込んだモデルを使う場合は `public/models/fish/<type>.glb` を置くと
`createFishGeometry` がそちらを優先します（Draco / Meshopt / KTX2 対応）。

## 7. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| スマホでセンサー許可のダイアログが出ない | HTTPSでアクセスしていない。`npm run start:https` を使う |
| 許可したのにポイが動かない | ページを再読み込み。iOSは許可がタップ内でのみ要求できるため |
| ポイが少しずれた位置で止まる | スマホを自然に構えたまま次のゲームを待つと自動で再キャリブレーション |
| 画面がカクつく | 運営コンソールで金魚の数を減らす / 高品質描画をOFF |
| スマホがスリープする | 画面の自動ロックを長めに（Wake Lock非対応端末向け） |
| QRを読んでも開けない | 自己署名証明書の警告を承認する。または同じWi-Fiにいるか確認 |
